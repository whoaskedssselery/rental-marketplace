# Маркетплейс аренды — КР2

Настольное приложение на JavaFX поверх PostgreSQL: пользователи, объекты аренды, заявки на аренду и отзывы. Есть CRUD через окна и формы, поиск, фильтры, сортировка, статистика и экспорт в Excel.

Архитектура: FXML (View) -> Controller -> Service -> Repository/DAO (JDBC) -> PostgreSQL.

Консольная версия из КР1 осталась в истории: тег `kr1-final`.

## Требования

- Java 21
- Maven 3.9 или новее
- Docker с `docker compose` (на Windows - Docker Desktop, он должен быть запущен)

Проверить версии: `java -version`, `mvn -v`, `docker compose version`.

## Первый запуск

1. Создать файл настроек (пароль БД хранится только в нём, файл в `.gitignore`) и при желании поменять пароль:
   ```bash
   cp .env.example .env
   ```
   Приложение читает `DB_URL`, `DB_USER`, `DB_PASSWORD` из переменных окружения, а если их нет - из `.env`. `docker compose` берёт `POSTGRES_*` из того же файла.
2. Поднять базу данных и дождаться готовности:
   ```bash
   docker compose up -d --wait
   ```
3. Проверить, что контейнер `healthy`:
   ```bash
   docker compose ps
   ```
4. Запустить приложение:
   ```bash
   mvn javafx:run
   ```

Если база не запущена, приложение покажет сообщение об ошибке подключения и закроется. Сначала всегда Docker и база, потом приложение.

Остановка базы без потери данных:

```bash
docker compose down
```

Не добавляйте `-v`: это удалит том с данными.

## Что умеет приложение

Главное окно с вкладками:

- **Заявки** (основная сущность): таблица, добавление, изменение дат (только у новой заявки), смена статуса по допустимым переходам, удаление с подтверждением, подробности. Над таблицей поиск (объект, арендатор, владелец), фильтры (статус, владелец, период) и сортировка.
- **Объекты**: CRUD, под таблицей заявки выбранного объекта.
- **Пользователи**: CRUD, под таблицей объекты пользователя и его заявки.
- **Отзывы**: CRUD, поиск, фильтр по оценке, сортировка, средний рейтинг объекта.
- **Статистика**: 12 показателей, заявки по статусам, объекты по категориям, заявки за выбранный период.

Кнопка «Обновить» перечитывает данные активной вкладки. Кнопка «Экспорт» выгружает в `.xlsx` то, что сейчас показано в таблице активной вкладки, «Экспорт всех вкладок» - все вкладки одной книгой. Путь файла выбирается в окне сохранения.

## Структура проекта

- `fx/` - интерфейс: `FxApplication` (точка входа), `AppContext` (создание сервисов), `controller/` (контроллеры окон), `support/` (диалоги, проверка форм, сообщения об ошибках, общие помощники таблиц и списков)
- `src/main/resources/fxml/` - разметка окон и форм, `css/app.css` - оформление
- `model/` - сущности `User`, `Listing`, `RentalRequest`, `Review` и перечисления
- `repository/` - доступ к БД через JDBC (`PreparedStatement`), по классу на таблицу, интерфейс `CrudRepository`
- `service/` - бизнес-правила: пользователи, объекты, заявки (поиск, фильтры, сортировка), отзывы, статистика, экспорт
- `exception/` - собственные исключения
- `util/` - пул соединений HikariCP и настройки подключения (`DatabaseManager`)
- `db/init.sql` - схема и тестовые данные, `db/patches/` - патчи для уже созданных баз

SQL есть только в `repository/`, бизнес-правил в контроллерах нет, ошибки показываются пользователю понятным текстом (технические подробности пишутся в журнал).

## Проверки

```bash
mvn verify
```

Запускает форматирование (Spotless, google-java-format), тесты, покрытие (JaCoCo) и линтер (Checkstyle, правила в `config/checkstyle.xml`). Отформатировать код автоматически: `mvn spotless:apply`. В `.editorconfig` заданы отступы для IDE.

Тесты сервисов используют Fake-репозитории из `src/test/java/.../repository/` (без БД). Интеграционные тесты JDBC используют запущенную БД и пропускаются, если она недоступна. Те же проверки запускает CI (GitHub Actions) на каждый push и pull request.

## Сброс базы данных

Схема и тестовые данные (`db/init.sql`) применяются только при первом запуске контейнера. Чтобы применить изменения заново (данные из базы пропадут):

```bash
docker compose down -v
docker compose up -d --wait
```

Чтобы добавить таблицу отзывов (`reviews`) в уже созданную базу без потери данных, выполните патч (повторный запуск безопасен):

```bash
docker exec -i rental-marketplace psql -U <POSTGRES_USER> -d <POSTGRES_DB> < db/patches/2026-10-reviews.sql
```

## Если не запускается

- **Не подключается к базе.** Docker Desktop не запущен или контейнер не `healthy`: запустите Docker и выполните `docker compose up -d --wait`.
- **Порт занят.** Измените `DB_PORT` в `.env` и порт в `DB_URL`, затем `docker compose up -d --wait`.
- **Ошибка авторизации в БД после смены пароля.** Том базы хранит старый пароль. Верните прежний пароль в `.env` или пересоздайте том (`docker compose down -v`, данные пропадут).
- **Нет таблицы `reviews`.** База создана до появления отзывов: примените патч из раздела выше.
- **Не та версия Java.** Нужна Java 21: `java -version`. На более новой JDK проект собирается (используется `--release 21`), но запускать проверенно на 21.
- **Окно не открывается или падает на старте.** Смотрите вывод `mvn javafx:run`, подробности ошибок пишутся в журнал в консоль.
